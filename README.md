# 门店地图插件（飞书多维表格仪表盘）

在飞书多维表格仪表盘中，根据多维表的经纬度数据渲染门店点位地图。底图使用腾讯地图 GL JS（合规底图）。

## 一、本地开发

```bash
npm install
npm run dev        # 默认 http://localhost:5173
```

### 在飞书里调试

1. 打开多维表 → 仪表盘 → **+ 添加组件 → 插件 → 更多**（插件市场）
2. 右上角 **添加自定义插件** → 服务地址填 `http://localhost:5173` → 确定
3. 插件以 iframe 加载，改代码 Vite HMR 会实时刷新

### 脱离飞书调试 UI（可选）

本地浏览器打开 `http://localhost:5173/?mock=1` 会走 mock 数据（真实 52 条门店），不会调用飞书 SDK，
但**会真实加载腾讯地图**——所以本地要能出图，key 的白名单里得加上 `http://localhost:5173`。

> `src/mock.ts` 里的 mock 点位是从「门店经纬度」导出的**真实 52 条门店数据**（便于本地核对坐标是否落在正确位置）。门店位置属公开信息，但如果不希望它进入公开仓库，把 `MOCK_POINTS` 换回示例坐标即可。

> 注意：服务地址只能填 `localhost`，不能填局域网 IP。https 页面嵌入 http iframe 仅对 localhost 豁免。

## 二、腾讯地图 key

`src/mapKey.ts` 里已内置一个默认 key，配置面板留空即可直接使用，不用每个组件重复粘贴。

**关于 key 的安全（重要）**：前端 key 一定会暴露在 JS 产物里，混淆没有意义。

- **飞书仪表盘插件场景**：不要依赖 Referer 白名单。飞书把插件嵌在 iframe 中，发往地图的请求 Referer 要么为空、要么是飞书域名，**不在白名单内会被直接拒绝，导致地图白屏**。因此飞书场景应保持白名单**关闭**，仅靠下面的「每日调用量上限」兜底即可。
- 其他场景（自己网页嵌入）可用 Referer 白名单：只填 `https://chensjfish.github.io`，本地调试可临时加 `http://localhost:5173`。

1. 打开[腾讯位置服务控制台](https://lbs.qq.com/dev/console/application/mine) → 找到该 key → 编辑
2. 确认已启用 **JavaScript API GL** 产品（不是 WebServiceAPI / 小程序）
3. 配置**每日调用量上限**，避免 key 暴露后被他人盗刷产生账单

要换 key 时改 `src/mapKey.ts` 的 `DEFAULT_MAP_KEY` 即可；配置面板里单独填的 key 优先级更高。

## 三、插件配置

| 配置项 | 说明 |
|---|---|
| 数据表 | 选择包含门店坐标的数据表，例如「门店经纬度」 |
| 门店名称字段 | 点击点位时气泡显示的标题，可选 |
| 坐标来源 | `经度字段 + 纬度字段`（文本/数字均可）或 `单个地理位置字段` |
| 经纬度顺序颠倒 | 点位整体偏移、或跑到海外时勾选，交换经纬度 |
| 省份字段 | 可选；配置后地图顶部出现「省份」下拉筛选 |
| 城市字段 | 可选；配置后地图顶部出现「城市」下拉筛选（城市随所选省份联动） |
| 品牌字段 | 可选；配置后点位按品牌着色，并在地图顶部出现「品牌」多选下拉筛选 |
| 门店功能字段 | 可选；配置后地图顶部出现「门店功能」多选下拉筛选 |
| 门店类型字段 | 可选；配置后地图顶部出现「门店类型」多选下拉筛选 |
| 经营模式字段 | 可选；配置后地图顶部出现「经营模式」多选下拉筛选 |
| 腾讯地图 key | 留空即用内置默认 key，见上一节 |

配置保存在仪表盘的 `customConfig`，每张仪表盘组件独立保存。

> 筛选栏只在配置了对应字段、且数据里该字段有值时出现；选「省份」会自动清空已选「城市」，便于逐级下钻。**品牌、门店功能、门店类型、经营模式均为多选**，下拉框内可输入关键词模糊搜索、可勾选多个值，选「全部」清空筛选。

## 四、坐标系

飞书地理位置字段返回的坐标与腾讯地图同为 **GCJ-02**，正常情况下无需转换。
首批数据上线前，建议挑 1-2 个已知门店对比实际位置确认；若整体偏移约几百米到 1 公里，通常是坐标系问题或经纬度顺序颠倒。

插件会过滤掉超出中国及周边范围（经度 70-140、纬度 0-60）的脏数据，并在左下角显示「成功打点 N 个 / 跳过 M 条」。

## 五、部署到 GitHub Pages

1. 仓库设为 **Public**，Settings → Pages → Source 选 **GitHub Actions**
2. `git push` 到 `main` 分支，`.github/workflows/deploy.yml` 会自动构建并发布
3. 部署完成后得到 `https://chensjfish.github.io/V/`，把它填回仪表盘的插件服务地址即可

调试期建议保留两个插件实例：一个指向 `localhost:5173`（本地联调），一个指向 Pages 地址（线上验证）。

## 六、已知限制

- 通过**独立分享链接**打开的仪表盘不会展示插件
- 插件默认仅添加者本人可见，要开放给他人需提交官方发布审核
- 数据量很大时（数千点以上）建议改为聚合展示
